## 2. Schema Creation Mechanism

Instead of EF migrations, the project uses **`Database.EnsureCreatedAsync()`** to
initialise the PostgreSQL schema at application startup.

### Call Site

**File**: `Bookstore.Web/Startup/MiddlewareSetup.cs`  
**Method**: `ConfigureMiddlewareAsync(WebApplication app)`

```csharp
// Create the database
using (var scope = app.Services.CreateAsyncScope())
{
    await scope.ServiceProvider
               .GetService<ApplicationDbContext>()!
               .Database.EnsureCreatedAsync();
}
```

### How EnsureCreatedAsync Works with Npgsql

`EnsureCreatedAsync()` inspects the **live EF Core model** (produced by `OnModelCreating`)
and issues DDL directly against the connected database if the schema does not yet exist.
Because the `ApplicationDbContext` is now wired to `Npgsql.EntityFrameworkCore.PostgreSQL`,
all DDL emitted will be **PostgreSQL-native** — there is no SQL Server DDL involved at
runtime.

| Concern | Detail |
|---------|--------|
| Provider at DDL time | `Npgsql.EntityFrameworkCore.PostgreSQL 8.0.0` |
| Schema / table names used | Defined in `OnModelCreating` via `entity.ToTable(name, schema)` |
| Target PostgreSQL schema | `bobsbookstore_dbo` (all entities) |
| Identity columns | Npgsql default → `GENERATED BY DEFAULT AS IDENTITY` |
| Boolean storage | EF Core `bool` → PostgreSQL `boolean` (native, no int conversion needed at DDL level) |
| DateTime storage | `Npgsql.EnableLegacyTimestampBehavior = true` switch active; stored as `timestamp without time zone` |
