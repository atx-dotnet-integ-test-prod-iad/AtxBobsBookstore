STATEMENT 4: Select Authors by Hire Year with Age Calculation
===============================================================================
Source File: AuthorsController.cs
Method: SelectAuthorsByHireYear
Line: 214

Original SQL Server Statement:
SELECT BusinessEntityID, FORMAT(ModifiedDate, 'yyyy-MM-dd HH:mm:ss') AS FormattedModifiedDate, DATEDIFF(YEAR, BirthDate, GETDATE()) AS Age FROM bobsbookstore_dbo.author WHERE DATEPART(YEAR, HireDate) = @HireDate;

DMS Conversion Status: FAILED (Metadata model creation error)

Manual PostgreSQL Conversion:
SELECT BusinessEntityID, TO_CHAR(ModifiedDate, 'YYYY-MM-DD HH24:MI:SS') AS FormattedModifiedDate, DATE_PART('year', AGE(NOW(), BirthDate)) AS Age FROM bobsbookstore_dbo.author WHERE EXTRACT(YEAR FROM HireDate) = @HireDate;

Manual Conversion Rationale:
1. FORMAT(ModifiedDate, 'yyyy-MM-dd HH:mm:ss') -> TO_CHAR(ModifiedDate, 'YYYY-MM-DD HH24:MI:SS')
   - FORMAT is SQL Server specific function for date/time formatting
   - TO_CHAR is PostgreSQL equivalent with different format pattern syntax
   - Format pattern adjusted: yyyy->YYYY, HH->HH24, mm->MI, ss->SS

2. DATEDIFF(YEAR, BirthDate, GETDATE()) -> DATE_PART('year', AGE(NOW(), BirthDate))
   - DATEDIFF calculates difference between dates in SQL Server
   - PostgreSQL uses AGE() to calculate interval, then DATE_PART() to extract years
   - AGE(NOW(), BirthDate) calculates age from birth date to current timestamp
   - DATE_PART('year', ...) extracts the year component from the interval

3. GETDATE() -> NOW()
   - GETDATE() is SQL Server function for current timestamp
   - NOW() is PostgreSQL equivalent (CURRENT_TIMESTAMP also acceptable)

4. DATEPART(YEAR, HireDate) -> EXTRACT(YEAR FROM HireDate)
   - DATEPART extracts date component in SQL Server
   - EXTRACT is PostgreSQL standard SQL function for date component extraction

5. Schema and table name (bobsbookstore_dbo.author) remain unchanged
6. Parameter syntax (@HireDate) remains compatible

Notes:
- Date function transformations are critical for correct functionality
- Format patterns are case-sensitive in PostgreSQL
- AGE() returns INTERVAL type, requiring DATE_PART() extraction
- This statement has the most complex transformations of all four statements
